# 888 Cube Client

Python-клиент для отправки одиночных кадров, готовых серий и процедурных эффектов на монохромный LED-куб 8×8×8.

Клиент рассчитан на POSIX-системы с `termios` и не требует внешних Python-библиотек. По умолчанию используется порт `/dev/cu.usbmodem2101`, скорость 9600 бод и команда прошивки `draw `.

## Совместимость с прошивкой

Документированная версия прошивки: [`888-cube v1.1.0`](https://github.com/lunevvs/888-cube/tree/v1.1.0). Эту строку нужно обновлять при синхронизации клиента со следующими изменениями прошивки.

Формат команды `draw` совместим с `v1.0.1`, но для надёжного накопления кадра, штатного подтверждения и обработки тайм-аутов рекомендуется `v1.1.0`. Совместимость более новых версий нужно сверять с их изменениями. Описание всех команд и serial-протокола находится в проекте [`888-cube`](https://github.com/lunevvs/888-cube).

## Быстрый старт

Проверить кадр без открытия порта:

```bash
python3 draw.py --dry-run draw-example/draw-bottom-layer
```

Отправить один кадр:

```bash
python3 draw.py draw-example/draw-bottom-layer
```

Циклически воспроизводить каталог кадров с частотой 4 кадра/с:

```bash
python3 draw.py draw-series/rotating-diagonal
```

Воспроизвести серию три раза и выключить куб:

```bash
python3 draw.py --cycles 3 draw-series/rotating-diagonal
```

Запустить процедурный алгоритм:

```bash
python3 draw.py --algorithm water_surface
```

Повернуть любой кадр или алгоритм другой гранью к зрителю и выбрать его ориентацию:

```bash
python3 draw.py --front left --bottom down --algorithm notification_warning
python3 draw.py --front up --bottom left draw-series/rotating-diagonal
```

Параметр `--front` (также доступен как `--front-face`) принимает `front`,
`back`, `left`, `right`, `up` или `down`. По умолчанию используется `front`.
Параметр `--bottom` (или `--bottom-face`) задаёт грань куба, которая должна
находиться снизу от выбранной лицевой грани. Лицевая и нижняя грани должны быть
соседними: нельзя выбрать одну и ту же грань или противоположные грани.

Если `--bottom` не задан, клиент сохраняет прежнюю ориентацию `--front`:

- для `front`, `back`, `left` и `right` снизу находится `down`;
- для `up` снизу находится `front`;
- для `down` снизу находится `back`.

Поворот применяется ко всем кадрам непосредственно перед отправкой, поэтому он
одинаково работает с файлами, сериями и процедурными алгоритмами.

Получить список всех алгоритмов, их приоритетов и встроенных настроек:

```bash
python3 draw.py --list-algorithms
```

## Bash completion

Подключить completion в текущей оболочке:

```bash
source completions/draw.py.bash
```

После подключения запускайте клиент как исполняемый файл, чтобы Bash применял
completion к `draw.py`:

```bash
./draw.py --front up --bottom <Tab>
./draw.py --algorithm notification_<Tab>
./draw.py draw-series/<Tab>
```

Completion подсказывает параметры командной строки, алгоритмы из каталога
`algorithms`, допустимые грани, serial-порты, каталоги и файлы кадров размером
64 байта. Для `--bottom` предлагаются только грани, соседние с уже выбранной
`--front`.

Для автоматического подключения добавьте в `~/.bashrc` путь к completion из
локальной копии проекта, например:

```bash
source /path/to/888-cube-client/completions/draw.py.bash
```

## Формирование кадра

Файл кадра содержит ровно 64 сырых байта. Каждый байт управляет одним вертикальным столбиком из восьми светодиодов.

Координаты имеют диапазон 0–7:

- `x = 0` — правая сторона, `x = 7` — левая;
- `y = 0` — лицевая сторона, `y = 7` — задняя;
- `z = 0` — нижний уровень, `z = 7` — верхний.

Индекс столбика и бит светодиода:

```python
byte_index = x * 8 + y
bit_mask = 1 << z

frame = bytearray(64)
frame[byte_index] |= bit_mask
```

Каждые восемь последовательных байт образуют вертикальный слой. Слои идут справа налево; внутри слоя столбики идут от лицевой стороны к задней.

Примеры:

- нижний горизонтальный слой — 64 байта `0x01`;
- верхний горизонтальный слой — 64 байта `0x80`;
- лицевая грань использует индексы `0, 8, 16, …, 56`;
- диагональ справа снизу налево вверх использует значения `0x01, 0x02, …, 0x80` по индексам `0, 8, …, 56`.

Файл должен быть бинарным, без префикса `draw ` и без перевода строки. Нулевые байты являются частью кадра и должны сохраняться на своих позициях.

## Серии кадров

При передаче каталога клиент читает все `*.bin` в лексикографическом порядке. Рекомендуется нумеровать файлы с ведущими нулями:

```text
frame-000.bin
frame-001.bin
frame-002.bin
```

Все файлы обязаны иметь размер 64 байта. Без `--cycles` каталог повторяется до `Ctrl+C`; после остановки или конечного числа циклов клиент отправляет пустой кадр.

Частота задаётся параметром `--fps`:

```bash
python3 draw.py --fps 8 draw-series/rotating-diagonal-depth
```

Готовые серии:

- [`rotating-diagonal`](draw-series/rotating-diagonal/README.md) — вращение диагонали на лицевой грани;
- [`rotating-diagonal-depth`](draw-series/rotating-diagonal-depth/README.md) — вращение с движением в глубину и обратно.

## Процедурные режимы

Каждый режим находится в отдельном файле `algorithms/<name>.py` и выбирается тем же именем:

```bash
python3 draw.py --algorithm double_helix
python3 draw.py --algorithm notification_warning
```

Реализованные общие эффекты:

- `water_surface`;
- `double_helix`;
- `tornado`;
- `bouncing_ball`;
- `falling_shapes`.

Реализованные уведомления:

- `notification_soft`;
- `notification_incoming`;
- `notification_reminder`;
- `notification_success`;
- `notification_error`;
- `notification_warning`;
- `notification_urgent`;
- `notification_progress`;
- `notification_waiting`;
- `notification_incoming_call`;
- `notification_background_complete`;
- `notification_connection_lost`;
- `notification_connection_restored`.

Подробное описание каждого режима, интерфейса расширения, приоритетов, FPS и числа циклов находится в [`algorithms/README.md`](algorithms/README.md).

Алгоритмы уведомлений содержат встроенные `default_fps` и `default_cycles`. Их можно переопределить:

```bash
python3 draw.py --algorithm notification_warning --fps 4 --cycles 1
python3 draw.py --algorithm notification_success --loop
```

Параметры конкретного алгоритма передаются через `--algorithm-option KEY=VALUE` или `-O`. Например:

```bash
python3 draw.py \
  --algorithm notification_progress \
  --algorithm-option progress=75
```

`notification_progress` принимает `progress=0..100`, не очищает последний кадр и оставляет достигнутое значение на кубе. Обычно моргают последние 10 процентных пунктов заполнения. При 100% внутренний объём остаётся включённым, а внешняя оболочка моргает.

## Параметры соединения

```bash
python3 draw.py \
  --port /dev/cu.usbmodem2101 \
  --baud 9600 \
  --reset-delay 0 \
  draw-example/draw-top-layer
```

По умолчанию клиент не ожидает подтверждения. Проверка ответа включается через `--ack`:

```bash
python3 draw.py --ack draw-example/draw-top-layer
```

Прошивка `v1.1.0` печатает имя принятой команды, а после полного кадра — отдельную строку `64`. Параметр `--ack` ожидает эту строку для каждого кадра. Для диагностики и одиночных кадров подтверждение полезно; при воспроизведении серий оно добавляет ожидание ответа после каждой отправки.

Если контроллер перезагружается при открытии порта, можно добавить паузу через `--reset-delay`. Значение `9600` сохраняется для совместимости настроек порта. На Arduino Leonardo и других платах с ATmega32U4 соединение работает через USB CDC, поэтому это значение не задаёт физическую скорость USB.

## Нюансы протокола и генерации

- Полная команда содержит 69 байт: ASCII `draw ` и 64 сырых байта кадра.
- Нельзя использовать `$(cat frame)`: shell удаляет нулевые байты и изменяет позиции данных.
- `draw.py` передаёт префикс и кадр одной бинарной записью. Прошивка `v1.1.0` также умеет накапливать команду из нескольких записей, если пауза между ними не превышает одну секунду.
- Перед запуском нужно закрыть `cat`, Serial Monitor и другие процессы, работающие с тем же портом.
- Serial-парсер `v1.1.0` работает в основном цикле, независимо от обработчика отрисовки Timer1, и не вызывает `Serial.flush()` при чтении.
- Прошивка сначала принимает все 64 байта во временный буфер и только затем атомарно заменяет кадр куба. При тайм-ауте она отвечает `ERR draw timeout` и сохраняет прежнее изображение.
- Предупреждение клиента о предельном FPS вычисляется по UART-формуле и для USB CDC является только консервативным ориентиром. Устойчивую частоту кадров нужно измерять на конкретной плате и операционной системе; увеличение `--baud` само по себе не ускоряет USB CDC.
- Протокол не содержит номера кадра или CRC. `--ack` подтверждает получение 64 байт, но не позволяет однозначно связать ответ с конкретным кадром после потери данных.
- У прошивки нет двойного кадрового буфера: новый кадр не копируется частично, однако его замена между выводом двух слоёв может дать кратковременный разрыв изображения.
