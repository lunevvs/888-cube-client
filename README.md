# 888 Cube Client

Python-клиент для отправки одиночных кадров, готовых серий и процедурных эффектов на монохромный LED-куб 8×8×8.

Клиент рассчитан на POSIX-системы с `termios` и не требует внешних Python-библиотек. По умолчанию используется порт `/dev/cu.usbmodem2101`, скорость 9600 бод и команда прошивки `draw `.

Описание прошивки и serial-протокола находится в соседнем проекте [`888-cube`](../888-cube/README.md).

## Быстрый старт

Проверить кадр без открытия порта:

```bash
python3 draw.py --dry-run draw-example/draw-bottom-layer
```

Отправить один кадр:

```bash
python3 draw.py draw-example/draw-bottom-layer
```

Циклически воспроизводить каталог кадров с частотой 4 кадра/с:

```bash
python3 draw.py draw-series/rotating-diagonal
```

Воспроизвести серию три раза и выключить куб:

```bash
python3 draw.py --cycles 3 draw-series/rotating-diagonal
```

Запустить процедурный алгоритм:

```bash
python3 draw.py --algorithm water_surface
```

Получить список всех алгоритмов, их приоритетов и встроенных настроек:

```bash
python3 draw.py --list-algorithms
```

## Формирование кадра

Файл кадра содержит ровно 64 сырых байта. Каждый байт управляет одним вертикальным столбиком из восьми светодиодов.

Координаты имеют диапазон 0–7:

- `x = 0` — правая сторона, `x = 7` — левая;
- `y = 0` — лицевая сторона, `y = 7` — задняя;
- `z = 0` — нижний уровень, `z = 7` — верхний.

Индекс столбика и бит светодиода:

```python
byte_index = x * 8 + y
bit_mask = 1 << z

frame = bytearray(64)
frame[byte_index] |= bit_mask
```

Каждые восемь последовательных байт образуют вертикальный слой. Слои идут справа налево; внутри слоя столбики идут от лицевой стороны к задней.

Примеры:

- нижний горизонтальный слой — 64 байта `0x01`;
- верхний горизонтальный слой — 64 байта `0x80`;
- лицевая грань использует индексы `0, 8, 16, …, 56`;
- диагональ справа снизу налево вверх использует значения `0x01, 0x02, …, 0x80` по индексам `0, 8, …, 56`.

Файл должен быть бинарным, без префикса `draw ` и без перевода строки. Нулевые байты являются частью кадра и должны сохраняться на своих позициях.

## Серии кадров

При передаче каталога клиент читает все `*.bin` в лексикографическом порядке. Рекомендуется нумеровать файлы с ведущими нулями:

```text
frame-000.bin
frame-001.bin
frame-002.bin
```

Все файлы обязаны иметь размер 64 байта. Без `--cycles` каталог повторяется до `Ctrl+C`; после остановки или конечного числа циклов клиент отправляет пустой кадр.

Частота задаётся параметром `--fps`:

```bash
python3 draw.py --fps 8 draw-series/rotating-diagonal-depth
```

Готовые серии:

- [`rotating-diagonal`](draw-series/rotating-diagonal/README.md) — вращение диагонали на лицевой грани;
- [`rotating-diagonal-depth`](draw-series/rotating-diagonal-depth/README.md) — вращение с движением в глубину и обратно.

## Процедурные режимы

Каждый режим находится в отдельном файле `algorithms/<name>.py` и выбирается тем же именем:

```bash
python3 draw.py --algorithm double_helix
python3 draw.py --algorithm notification_warning
```

Реализованные общие эффекты:

- `water_surface`;
- `double_helix`;
- `tornado`;
- `bouncing_ball`;
- `falling_shapes`.

Реализованные уведомления:

- `notification_soft`;
- `notification_incoming`;
- `notification_reminder`;
- `notification_success`;
- `notification_error`;
- `notification_warning`;
- `notification_urgent`;
- `notification_progress`;
- `notification_waiting`;
- `notification_incoming_call`;
- `notification_background_complete`;
- `notification_connection_lost`;
- `notification_connection_restored`.

Подробное описание каждого режима, интерфейса расширения, приоритетов, FPS и числа циклов находится в [`algorithms/README.md`](algorithms/README.md).

Алгоритмы уведомлений содержат встроенные `default_fps` и `default_cycles`. Их можно переопределить:

```bash
python3 draw.py --algorithm notification_warning --fps 4 --cycles 1
python3 draw.py --algorithm notification_success --loop
```

Параметры конкретного алгоритма передаются через `--algorithm-option KEY=VALUE` или `-O`. Например:

```bash
python3 draw.py \
  --algorithm notification_progress \
  --algorithm-option progress=75
```

`notification_progress` принимает `progress=0..100`, не очищает последний кадр и оставляет достигнутое значение на кубе. Обычно моргают последние 10 процентных пунктов заполнения. При 100% внутренний объём остаётся включённым, а внешняя оболочка моргает.

## Параметры соединения

```bash
python3 draw.py \
  --port /dev/cu.usbmodem2101 \
  --baud 9600 \
  --reset-delay 0 \
  draw-example/draw-top-layer
```

По умолчанию клиент не ожидает подтверждения. Проверка ответа включается через `--ack`:

```bash
python3 draw.py --ack draw-example/draw-top-layer
```

Если контроллер перезагружается при открытии порта, можно добавить паузу через `--reset-delay`.

## Нюансы протокола и генерации

- Полная команда содержит 69 байт: ASCII `draw ` и 64 сырых байта кадра.
- Нельзя использовать `$(cat frame)`: shell удаляет нулевые байты и изменяет позиции данных.
- Префикс и кадр должны передаваться одним бинарным сообщением; `draw.py` делает это автоматически.
- Перед запуском нужно закрыть `cat`, Serial Monitor и другие процессы, работающие с тем же портом.
- При 9600 бод передача 69 байт занимает около 72 мс; практический предел — примерно 13 кадров/с.
- Для десятков кадров в секунду понадобится увеличить baud rate одновременно в клиенте и прошивке.
- Текущая прошивка вызывает serial-парсер из обработчика прерывания и содержит `Serial.flush()` при чтении. Это создаёт риск зависания или неполного кадра; при зависании контроллер нужно перезапустить.
